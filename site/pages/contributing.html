The wayfinder map

Planned work hangs off one map issue. Each child ticket has a type.

Map issue (wayfinder:map)
├── wayfinder:research    find something out
├── wayfinder:prototype   build a throwaway to answer a question
├── wayfinder:grilling    stress-test a plan or decision
└── wayfinder:task        do the work

A ticket is free when all its blockers are closed and nobody is assigned. Assign yourself before you start, so nobody duplicates the work.

Code rules

The shipped tool follows four rules. Breaking one needs evidence and a maintainer decision first.

  • Pure Rust. No compiled C in the binary, so no -sys crates that build C.
  • lopdf is the only PDF writer.
  • The original file is never changed. Output always goes to a new file.
  • Dependencies are MIT or Apache licensed.

The crate uses edition 2024, so it needs Rust 1.85 or newer.

cargo build
cargo test
cargo clippy

The clean-room rule

MuPDF and Ghostscript are AGPL. Poppler is GPL. Their code must never reach PDFPundit, because that would bind PDFPundit to their licences.

AllowedNot allowed
Research reads them and quotes short passagesCopying their code into PDFPundit
Describing their behaviour in your own wordsSpecs that contain their code
Running them as baselines and oraclesPointing a coding agent at their source

Data rules

  • Use public corpora only.
  • Never commit a PDF that contains personal data.
  • Record the licence of every corpus you use.
  • Cache full texts in research/cache/, which git ignores. Never commit them.
  • Don't scrape in breach of a site's terms.

Decisions

Reviewed research decisions go in research/committees/ as minutes. Decisions that change the product become ADRs in docs/adr/.

If your change contradicts an ADR, say so in the pull request and give the evidence.

Pull requests

  1. Branch from main.
  2. Keep one change per pull request.
  3. For research changes, run kb_validate.py. It must print 0 errors.
  4. For code changes, run cargo test.
  5. Say which issue the pull request closes.

Editing this wiki

The wiki lives in site/ in the repository. Each page is a fragment in site/pages/. Every page has an "Edit this page" link at the bottom.

python site/build.py              # writes site/dist/
python -m http.server -d site/dist # preview at localhost:8000

A push to main that touches site/ publishes the wiki through GitHub Pages.
