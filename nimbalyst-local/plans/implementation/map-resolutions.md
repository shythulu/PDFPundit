## Ticket resolutions

### #2 Research: repair-method selection, how findings map to a repair plan · **resolved (structure), research-pending (weights)**

Answer: no published selection matrix exists; MCDM (AHP/TOPSIS) is the wrong tool (rank reversal, subjective weights). Adopt the three-layer engine from SE Q1: (A) a transparent feasibility table keyed on findings (`/Encrypt` → none; C1–C3 only → Resave; C4/C5/C10 → Resave and TemplateAssemble both run; C9 orthogonal, salvage first; C7 with surviving ToUnicode → TemplateAssemble + Resave comparison; C6/C8 → TemplateAssemble + font inference), (B) run every feasible candidate (the candidate set is bounded by the table, and the only budgets inside a candidate count work units, never time: D-041), (C) pick by the lexicographic verification tuple (V0 hard gates, V1 retention, V2 text plausibility, V3 preservation, V4 prior Resave then smaller). Escalation reasons: `FontPick`, `FontUnreproducible` (policy prompt, batched per family, `fonts.unreproducible = ask|substitute_generic|text_only`, default `ask`), `CandidatesDisagree`, `OutOfDistribution`, `NoCandidatePassed` (informational). The design's 0.60 reachability constant leaves the decision and survives only as a tie-break prior. Validation: ASlib-style, fraction of the single-best-to-oracle gap closed per class.

Not given: numeric within-tier weights (to be learned from Resave-vs-TemplateAssemble pairs on a grouped split) and the auto-accept threshold (risk-targeted, needs ~150 error-free labelled slots). Whether the product ships a learned or fixed selector is a PR #19 board question (WP-3.13); the panel defaults to fixed tiers for v1 (D-008).

Evidence: SE Q1–Q3 (merged PR #16), RR "Generate, verify and calibrate" and ranked changes #7/#8. Amendment: ADR-0003 cited by the ticket does not exist; the planner decision is ADR candidate A-2 in `decision-log.md`.

### #4 Research: hayro-interpret as the benchmark text extractor · **resolved (FR-04; the M3 glyph spike is answered)**

Answer: usable, through the `Device` trait rather than a text API. Implement `Device::draw_glyph_run` and run `interpret_page(&page, &mut Context::new(page.initial_transform(true).to_kurbo(), Rect, &InterpreterCache, pdf.xref(), InterpreterSettings), &mut dev)`; glyphs arrive in content order, one `draw_glyph_run` per `Tj`/`TJ`. Each `PositionedGlyph` gives `as_unicode() -> Option<BfString>` (ToUnicode applied for Type0, Type1, TrueType, Type3; 57,784/57,784 glyphs mapped on the clean fixture; with ToUnicode removed, Type0 glyphs return `None`) and `transform()`; origin and em size come from `props.transform * glyph.transform()` (pre-scaled by 1/1000); advance from `OutlineGlyph::advance_width()`. No bbox, no font-size field, no ascent/descent. Font name and flags: `font_data()` is `None` for Type1, non-embedded and Type3 fonts (6 of 17 in the fixture); a side table keyed by `Dict::cache_key()` (= `font_cache_key()`) over `pdf.objects()` resolved 17/17. Corrupted input: no panic in 5,900 fuzz runs; `interpret_page` returns `()` and drops damage silently (C9: a page lost with no warning; C6: garbage text, doubled glyph count, 0 warnings); `Pdf::new(Vec<u8>)` loads C1–C4/C10-style damage by scanning for objects and the last `/Type /Catalog` (page order by file offset when the tree is gone); it fails only when both the trailer and the Catalog are gone. Determinism: identical glyph dumps across processes. Features: keep `embed-fonts` (required), `embed-cmaps` +465 KB kept by default (D-037). Purity: ~64 crates, no `cc`, no `-sys`; Foxit fonts carry a BSD-style notice to ship. Consequences: (1) `src/pdf/text.rs` is ticket T-36, used by verify V1/V2, the bench and export; (2) hayro is a gate on repaired output only, never a corruption detector; (3) hidden-OCG text is absent (D-038). The fallback content-stream interpreter is not needed. The TOOL-361 hint ("no text API") was about the rasteriser and is literally true of the interpreter too, but the Device route works.

### #6 Research: lopdf as sole emitter and strict parser · **resolved (FR-06)**

Resolved: the loader question is moot for the design (the carver is the loader; lopdf 0.45 opens no C1/C10 file, OBS-1103) and strict reload remains a verification gate. PR #19's flag ("lopdf as sole loader and emitter contradicted") concerns loading; the emitter decision stands (charter §5). Bump to 0.45.0 (D-022), `default-features = false` (no `cc`/`-sys`, no rayon, no clock crates).

Writer capabilities (read from the 0.45.0 source and run in a probe): from-scratch documents with chosen ids work (`set_object`, gaps become separate xref subsections, PR #558); `save_to` emits a correct header (`%PDF-x.y\n%` + four bytes ≥ 0x80), 20-byte xref entries and a trailer of exactly the keys set plus `/Size`; save never compresses, never writes `/CreationDate`, `/ModDate`, `/Info` or `/ID`; randomness is used only in encryption; two identical builds are byte-identical; object streams and xref streams appear only on explicit request (`save_modern`, `use_object_streams`, `use_xref_streams`). Three defaults bite: (1) `Document::new()` defaults to an xref **stream** (issue #434) and `SaveOptions{use_xref_streams:false}` does not force a table, so set `doc.reference_table.cross_reference_type = XrefType::CrossReferenceTable`; (2) `set_object` never touches `max_id` and `/Size` is always `max_id + 1` (ids 5/9/20/30 with `max_id = 0` gave `/Size 1`), so set `max_id` by hand; (3) re-saving a loaded document leaks `/Type /XRef`, `/W`, `/Index`, `/Length` into a classic trailer and `save_to` mutates the trailer, so build a fresh `Document` with a whitelisted trailer. Also: `Object::Real` is `f32` (NaN/inf print invalid), offsets are `u32` (> 4 GiB truncates silently), `/Length` goes stale if `stream.content` is poked (use `Stream::new`/`set_content`). Strict load is `load_mem_with_options(LoadOptions{strict:true, max_decompressed_size: Some(n), ..})`: it rejects header junk after the version, 19-byte xref entries, any startxref/xref/trailer failure (no reconstruction), wrong stream `/Length`, object-load errors and a missing `/Size`; it does **not** check `/Root`, `endobj` or the page tree, so V0 keeps its own graph check and the hayro render. `max_decompressed_size` caps ObjStm/XRef decoding only; content streams use `decompressed_content_with_limit`. Open bugs: #434, #581 (`linearize` unused), #575 (stale `/Prev`, not reproduced), #569 (limit errors swallowed in lenient and encrypted paths), #446/#449 (weak recovery: consistent with "the carver is the loader"). These are now the T-12 writer rules; D-019 is settled.

### #7 Research: REPDF's exact corruption-induction procedure · **resolved**

Per-class table (OBS-0001..0004, corpus_characterize.csv): C1 12-byte header span, 11–12 bytes differ; C2 whole classic xref removed (Save As 21–39 KB; Print 2.4–4 KB); C3 210–215 bytes (Save As) / 23–24 (Print) removed; C4 45–128 bytes removed around `/Pages`/`/Kids`/`/Count`; C5 exactly 8 bytes (one `N 0 obj` + EOL) in all 100 files; C6 `/Font` entry removed (Print 153–411 B; one defective Save-As file kept 7.7%); C7/C8 font (and ToUnicode) stream data overwritten in place with 0x20, size unchanged (C7 11–22 streams, C8 19–44); C9 12–30 random-byte replacements per file, one per damaged Flate stream (7–26 streams), about a third outside Flate data, only 3.1% single-bit; C10 exactly 70.0% kept. The paper's own text (§5.1) is one line per class and says "one byte" for C9; the corpus is authoritative. Fixture spec: `plan.md` T-03a (structural corruptors) and T-03b (the measured-distribution C9 corruptor). Amendment: TD §4.5/§8/§16 "flips exactly one byte" is superseded.
