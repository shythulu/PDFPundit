## 1. What the plan builds toward

The goal (DA:25-57, decided 2026-09-26): serious people feed PDFs to a cat; results beyond reproach (originals untouched, deterministic, offline, measured on REPDF); the cat is the only way in (no CLI); artefacts carry no cat.

The map's destination (#1, charted 2026-09-04) stops at "the first verified `<name>.repaired.pdf`, Latin fonts only, TUI past it, headless-first with a dev CLI". That predates the no-CLI decision and the merged research. This plan charts to a **re-drawn destination**. **The canonical text is the one in `map-resolutions.md` ("Proposed destination amendment", D-001); it is quoted here verbatim and must not drift** (goal-r2-q5: revisions 3–4 carried two different texts):

> Every decision needed to build (a) the engine from core types through the first `<name>.repaired.pdf` that passes the verification gates (strict lopdf reload, hayro render, re-diagnose clean, retention against the carve) and is scored on the REPDF corpus with the text-layer metric family and, per release, REPDF's OCR word-recall metric (the per-release leg depends on D-014), (b) the decided UI (cat renderer, director with the chomp and kitty tracking, view model, layout seam with full and widget adapters, themes, the browse picker) so that the cat is the only way to drive the engine, and (c) the Markdown export action, is locked; the build order is a sequence of one-session, test-gated implementation tickets. No command-line entry point exists at any point in the sequence, and the binary refuses to run without a terminal. Latin (en/fr/es) fonts only. The custody mode and OCR lie past it.

Markdown export is inside the destination because its deciding questions are closed (D-024, D-048, D-060) and the goal names it ("repair and Markdown creation", DA:67). The OCR-metric clause is the dev-tooling harness T-38; its per-release Document AI leg is money (D-014) and publication of any number is D-063.

What is **in** this plan: engine phases 0–2, jobs/config/persistence, the UI modules decided in UI D2/D3/D5 and the mockup plus the M1 browse picker, the benchmark metric module, the CI smoke job and the OCR word-recall harness (T-38a/b, local PaddleOCR leg), the text extractor (T-36, now Phase 1), the font-DB core and template builder (T-27, T-29), kitty OSC 72 (T-31, pending one live byte capture), Markdown export (T-32a/b, re-scoped). What is **blocked**: the inference scorer's assets and C7/C8 (D-010 scope, D-011 word-list licence), custody mode (design), OCR model delivery (D-050), the history/setup/error screens (need mockup frames from the user, D-048), publication of recovery rates (D-063), the first public binary (D-046 licence, D-065 likeness). Template PDFs are **not** files: `fontdb::template::build(font_bytes, gmap) -> Vec<u8>` builds the one-page carrier in memory through `pdf::write` at first use (deterministic, cached per process). Nothing generated is git-ignored, so a fresh checkout builds (eng-r1-q12).

Visibility (D-047 amended, revision 7): the crate's public surface is `run()`, `pdf::model`, `pdf::fixtures`, `pdf::write` and `pdf::fontdb::build::build_from_ttf` (what `tools/build-templates` calls); **the `engine` facade is `pub(crate)` unconditionally and there is no cfg, feature or flag that exposes it.** Revision 5's `--cfg pdfpundit_internal` from `.cargo/config.toml` is gone: goal-r3-fr2 measured that an environment `RUSTFLAGS` (even empty) replaces `build.rustflags`, so a developer's `target-cpu`, CI's `-Dwarnings`, coverage tools and cargo-dist (which always sets `RUSTFLAGS`, eng-r4-fr3) would have built the repo without the cfg and broken `main.rs`, `tests/` and `tools/`; and a git dependant could have switched it on with `RUSTFLAGS="--cfg pdfpundit_internal"`, which is a flag. So `main.rs` calls `pdfpundit::run()`, the facade end-to-end tests and the artefact deny-list test are inline `#[cfg(test)]` modules under `src/engine/`, the corpus harness is `src/bench/corpus.rs` (still an ignored test, D-002), and the only file under `tests/` is `guard.rs`, which spawns the binary. What this gives a git dependant: `run()`, which is the cat. Reaching the engine means editing the source, which is a fork. The crate is `publish = false`. Unit tests sit inline so they see `pub(crate)`; the inline facade tests use only `crate::engine::*` by convention (a comment at the top of each file; the contract check applies).

Determinism rules (apply to every engine ticket; **mechanics verified in a scratch crate, eng-r2-q11**: `clippy.toml` applies crate-wide, there is no per-path scoping, so the bans are crate-wide and the modules that legitimately need the types carry a module-level `#![allow]`):
- `BTreeMap`/`BTreeSet` or sorted `Vec` wherever order reaches output; `#![deny(clippy::iter_over_hash_type)]` in `src/pdf/mod.rs` and `src/engine.rs` (the restriction lint that catches `HashMap` iteration without banning `HashMap`); no rayon anywhere.
- **No time on any path that reaches output**: `std::time::{Instant, SystemTime, Duration}` are crate-wide `disallowed-types`; `src/ui/**`, `src/jobs.rs`, `src/panic_guard.rs` and `tests/guard.rs` carry `#![allow(clippy::disallowed_types)]` (the Director uses `Duration`; the runner polls; the guard test times a child). `src/library.rs` needs no allow: `RunRecord.started_at` is a `u64` of unix seconds produced in `jobs.rs` (D-076). Every budget counts work (D-041). Wall-clock may drive progress display and user cancellation in `jobs.rs` only, and cancellation yields `Err(Cancelled)`, never a different artefact. The lint job is `cargo clippy --all-targets --all-features -- -D warnings`, so test targets are linted too. The lint meta-tests (a scratch copy with an `Instant` under `src/pdf/` must fail; a `for _ in HashMap` must trip `iter_over_hash_type`) run as a **CI script step** with their own temp target dir, not inside `cargo test` (eng-r3-q9: inside `cargo test` they need clippy on every leg and contend for the outer target dir's lock).
- No platform libm on a selection path (D-076): the crate-wide `disallowed-methods` list is **every `f32`/`f64` method that lowers to libm**: `hypot`, `powf`, `powi`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh`, `exp`, `exp2`, `exp_m1`, `ln`, `log`, `log2`, `log10`, `ln_1p`, `cbrt`, `mul_add` (its `fma` fallback is platform libm and fusing differs by CPU, goal-r2-fr3), with **no** allows anywhere; `sqrt`, `abs`, `floor`, `ceil`, `round`, `round_ties_even`, `trunc`, `fract`, `signum`, `clamp`, `min`, `max` stay allowed (IEEE basic or exact). The cat and colour code call the `libm` crate (D-018). Ratios are stored as integer `(num, den)` pairs.
- **No non-string map key in any serialised type** (eng-r3-q1): serde_json refuses tuple keys (`ObjId = (u32, u16)` → "key must be a string", verified), so under `RepairReport`, `AnalysisResult` and `RunRecord` every map is keyed by `String` or is a `Vec` of pairs sorted by its key. A T-02b round-trip test over a fully populated fixture enforces it.
- **No raster-derived number reaches `verify` (D-059)**: `Retention` and `Plausibility` fields are built only from `Ratio`s and counts of interpreted (T-36 glyphs and `PaintCounts`) or carved data; `hayro::render` output is a V0 pass/fail gate and nothing numeric is read from its pixels; a T-12b test asserts `verify`'s inputs carry no pixel buffer and no pixel-derived value. Pixels are never golden-hashed.
- Every type named in a ticket's Interface line is defined by that ticket or a listed dependency (contract check, eng-r1-q8); every facade, jobs and report type is defined in full in T-02b (eng-r2-q1).

Release-binary rules (D-043, D-047, D-050, D-051): the binary ignores argv; it exits 2 with one line when stdin or stdout is not a terminal; **no environment variable changes engine output, input acceptance or the terminal guard in a release build**; the variables that are read are named here and read only for display and for locating config: `TERM` and `COLORTERM` (crossterm and the truecolor probe), `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME` (Linux), `APPDATA`, `LOCALAPPDATA`, `USERPROFILE` (Windows) through `appdirs.rs`; the run record stores the config path and `RepairReport` stores the settings snapshot and `font_db_sha256`, so which config was loaded is auditable (eng-r2-q10); `PDFPUNDIT_ASSETS`, panic injection and any test hook exist only under `cfg(debug_assertions)`; no HTTP/TLS/socket crate is in the lock file; `publish = false`.

## 4. The engine facade (ticket #10, proposed resolution) and the `Engine` contract (T-02b)

The synchronous pipeline lives in `src/engine.rs`; `jobs.rs` wraps it in threads. The interaction rendezvous is a trait the sync pipeline accepts, so the engine is testable without threads and the runner is testable without PDFs. **T-02b lands the signatures and a stub body right after T-02** so the UI lane and the runner never wait on the engine (eng-r1-q7).

```rust
// src/engine.rs  (facade; everything a caller must know)  the module is pub(crate); `pub` below means visible to the crate's
// other modules and its inline tests (D-047 amended)

pub use crate::pdf::model::{Finding, FindingKind, CorruptionClass, Severity, Location,
                            ByteSpan, Evidence, Repairability, ObjId, PaintCounts, SalvageGrade};

pub struct SalvageBudget { pub work: u64 /* W, default 700_000_000 */, pub deep_work: u64 /* default 10_000_000_000 */,
                           pub deep_pool: u64 /* per file, default 80_000_000_000; D-056 */,
                           pub max_search_stream: u64 /* raw bytes, default 4 MiB: above it no search runs (D-072; replaces `max_stream`) */ }   // D-041: counts work, never time
pub struct AnalyzeOptions { pub max_file_bytes: u64 /* warn > 512 MiB */, pub salvage_budget: SalvageBudget,
                            pub threads: NonZeroUsize /* D-066 */, pub scratch_cap: u64 /* bytes, default 1 GiB; D-072 */ }
    // threads and scratch_cap change wall-clock and peak memory only, never the digest (eng-r2-fr2, eng-r4-fr2); they are not in SettingsSnapshot
pub struct RepairOptions { pub passes: Option<Vec<CorruptionClass>> /* None = planner decides (GG §1) */,
                           pub font_policy: FontSourcePolicy, pub unreproducible: UnreproduciblePolicy,
                           pub default_page_size: PageSize, pub extract_unplaceable_images: bool }

pub struct AnalysisResult { pub meta: FileMeta, pub findings: Vec<Finding>, pub carve: CarveSummary,
                            pub font_slots: Vec<FontSlot>, pub stats: AnalyzeStats, pub input_sha256: [u8; 32],
                            #[serde(skip)] pub state: StateHandle }
    // StateHandle(Option<Arc<AnalysisState>>) (eng-r3-q1): Debug + Clone + Default; a hand-written PartialEq that is true when
    // both are None or Arc::ptr_eq, because AnalysisState is Debug only and `#[derive(PartialEq)]` would not compile.
    // AnalysisState (D-006 amended, eng-r2-q2): an opaque handle whose contents are pub(crate): CarveReport, ObjectGraph,
    // SalvageIndex, the input sha256. `repair` reuses it when present and its hash equals sha256(bytes); otherwise it
    // re-analyses (a result reloaded from history or evicted while parked has none) and the runner records which in the
    // RunRecord (D-073). Never serialised, never persisted.
pub struct RepairPlan { pub candidates: Vec<Toolpath>, pub prior: Toolpath, pub escalations: Vec<Escalation> }
pub struct RepairOutcome { pub output: Option<Vec<u8>>, pub report: RepairReport, pub status: OutcomeStatus /* Ok | Partial(Vec<String>) | Failed(String) */,
                           pub images: Vec<(String, Vec<u8>)> /* extracted image bytes travel here, to the export path; the report lists them by name, sha256 and length only (D-073) */,
                           pub analysis_state: AnalysisStateUse /* Reused | Rebuilt{reason} */ }

pub trait Engine: Send + Sync {
    fn analyze(&self, bytes: &[u8], opts: &AnalyzeOptions, sink: &mut dyn Progress) -> Result<AnalysisResult, Cancelled>;
    fn plan(&self, analysis: &AnalysisResult, opts: &RepairOptions) -> RepairPlan;
    fn repair(&self, bytes: &[u8], analysis: &AnalysisResult, plan: &RepairPlan, opts: &RepairOptions,
              fonts: &FontDb, ask: &mut dyn Interact, sink: &mut dyn Progress) -> Result<RepairOutcome, Cancelled>;
}
pub struct Pdfpundit;          // the real engine (bodies filled by T-14; T-02b stub: no findings + FileMeta; repair returns Failed("engine not built"))
pub fn analyze(..) / plan(..) / repair(..)   // free functions delegating to Pdfpundit, kept for src/engine/tests.rs

pub trait Progress { fn phase(&mut self, name: &'static str, index: u32, total: u32);
                     fn progress(&mut self, done: u64, total: Option<u64>);
```

`RepairReport`'s **shape is defined in T-02b** (every field listed there, `schema_version: u32`; eng-r2-q1) and T-14 fills its values without changing the shape. It records `engine_version`, `font_db_sha256` (D-051), **`settings: SettingsSnapshot`** (the knobs the output depends on) and **`interactions: Vec<InteractionRecord>`** (every request and reply, goal-r2-q12), every candidate's verification, the C9 survivor sets and the per-stream salvage grades with the `c9_summary` counts (D-041), `reals_narrowed` (D-075), shadows, extracted images by name, sha256 and length, and the fixed line "the original is digitally signed; the repaired file is not" when `FindingKind::Signed` fired (D-052). **The report is a pure function of the input bytes, the engine version, the settings snapshot and the interactions (D-073):** it carries no machine path, no placement tier and no "state reused or rebuilt" field (those are run facts and live in `RunRecord`, T-16, together with the config path and the output path), so two examiners' reports for the same input, version, settings and replies are byte-identical, and T-14 tests exactly that (analyze→repair against repair-from-history).

Depth check: a caller learns one trait with three methods, two more traits, and the model types; behind them sit carve, salvage, graph, rebuild, diagnose, plan, emit, verify. `UseBest` is the headless default the map asked for, reachable only from the inline tests and the runner. What this delivers, stated without overclaiming (goal-r2-q14, goal-r3-q7): **the shipped binary has no cat-free way in** (argv ignored, non-terminal refused, pre-frame input discarded, D-043), the crate is never published (D-047), and **the engine API is not part of the crate's public surface**: a git dependency on the public repo sees `run()` and nothing else, with no cfg, feature or flag that changes that (§3.1); reaching the engine means editing the source, which is a fork, and the source is public and can be forked, which no plan can prevent.

**T-05 Carver A: landmarks, assembly, extent ladder** · determined (TD §14.1–14.3; each rule below is stated in full here and grounded on permissive sources or ISO 32000, FR-g2 / eng-r1-fr4)
- Paths: `src/pdf/carver.rs` (+ `src/pdf/carver/landmarks.rs` if it grows).
- Interface: `pub(crate) fn carve(buf: &[u8], cancel: &dyn Fn() -> bool) -> Result<CarveReport, Cancelled>` (never fails except by cancellation; `cancel` is polled every 256 landmarks); `CarveReport {header: Option<HeaderInfo>, objects: Vec<CarvedObject>, orphans: Vec<Orphan>, xref_spans, trailer_spans, startxref: Vec<(u64, Option<u64>)>, eof_markers, notes: Vec<CarveNote>, stats}` with `heap_bytes() -> u64` (capacity of every owned `Vec` and `String`; lead-r4-fr1 measured the stand-in carve at 0.27–0.29 MB per MB of input on REPDF, about 1.2 KB per object, before ObjStm expansion); `CarvedObject {declared_id: ObjId, span: ByteSpan, body: Body{Dict|Stream{dict, data: ByteSpan, length_source}|Primitive|Unparsed}, kind: ObjectKind, origin: TopLevel|Compressed(ObjId), notes}`.
- Rules (each a test; stated in our own words):
  1. **Object header landmark.** A header is `<num> <gen> obj` where `num` and `gen` are decimal digit runs separated by single whitespace, and the header starts at the beginning of a line or after whitespace. Scanning finds the `obj` keyword and walks back at most 24 bytes to assemble the two numbers (24 is the design's own slack: ISO 32000-1 Annex C caps object numbers at 8,388,607, so a legal header is at most 17 bytes). `endobj` tails are dropped from the landmark list before matching. A header whose numbers overflow `u32` or whose `gen` exceeds 65,535 is ignored with a note.
  2. **Byte-order assembly** skipping dead ranges inside resolved stream spans, so keywords inside stream data never start an object.
  3. **Extent ladder** for stream data, in order: (a) declared `/Length` if `stream`+data+EOL+`endstream` fits exactly; (b) the **unique-endstream rule**: collect every `endstream` between the `stream` keyword and the next object header or EOF that is framed as EOL + `endstream` and followed by optional whitespace and `endobj`; if exactly one qualifies, the data ends at its preceding EOL (lopdf's definition; more than one → this rung yields nothing and the ladder continues); (c) deferred indirect `/Length` (T-07); (d) inflate probe (T-07); (e) the last `endstream` before the next header; (f) EOF with `TruncatedAtEof`. Any candidate extent that contains a header matching rule 1 at a line start is rejected (**no foreign header inside**, qpdf's check).
  4. **EOL after `stream`**: LF, CRLF, **bare CR** (D-030: accepted by qpdf, pdf.js, hayro and lopdf; ISO 32000-1 7.3.8.1 forbids it, so a `CarveNote::BareCrAfterStream` is attached), and space + EOL.
  5. Missing `endobj` ends the object at the next header or EOF.
  6. Caps: 1,000,000 landmarks and 1,000,000 objects (lopdf's cap); container elements are capped by the lexer at 5,000 (T-04); `CarveNote::CapHit` records any hit.
- Tests: fixtures C2/C3/C5/C10 carve all surviving objects with the right `LengthSource`; keyword-in-stream fixture yields no phantom objects; wrong-length (short/long/missing) fixtures hit ladder rows b/e; CRLF/LF/CR/space EOL; junk-prefixed header still finds objects; duplicate ids both carved; two `endstream`s in one stream fall past rung (b); `carve` never panics on 10k fuzzed buffers; cancellation mid-carve on a 64 MiB synthetic buffer returns `Err(Cancelled)` within 256 landmarks.
- Depends: T-02, T-03b (adversarial builders), T-04.

Search scratch is about 64 bytes per compressed byte (10,520 B checkpoints every 256 input bytes plus the output buffer). **Admission:** a search (phase 1 or phase 2) starts only while the sum of estimated scratch `66 × raw + max(12 × raw, 1 MiB)` over running searches is ≤ `scratch_cap` (1 GiB); a stream whose own estimate exceeds the cap runs alone. **Size limit:** a stream whose raw length exceeds `max_search_stream` (4 MiB) gets no search and becomes `Unsearched` (emit treats it as `ChecksumMismatch`/`Prefix`; the report says why), so no single search can need more than about 312 MiB and at most three overlap under the cap. Neither rule can change output: the phase-2 allocation is computed before any search (D-066) and each stream's result depends only on its own budget; eng-r4-fr2 found the digest, W and every row identical at 1, 4 and 8 threads with admission on (29 runs). REPDF's largest damaged stream is 2.6 MB, so neither rule binds on the corpus and the eng-r2-fr2 timings stand. `max_stream` (revision 6; it never said compressed or decoded, and was never a TD knob) is **replaced** by `max_search_stream` (raw bytes); the decoded ceiling is T-06's 256 MiB inflate cap.
- **Filter domain (eng-r2-q7).** Salvage runs on **the input to the Flate stage**: every filter before `/FlateDecode` in the chain (`/ASCII85Decode`, `/ASCIIHexDecode`, `/RunLengthDecode`) is decoded first through T-06's `decode_chain`, and every `edits` offset is an offset in that domain, never a raw-file offset. `FilterStage { earlier: Vec<Filter>, flate_parms: Option<Dictionary> /* /Predictor etc. */, later: Vec<(Filter, Option<Dictionary>)> /* e.g. DCT */ }` is recorded per stream so T-12a can rewrite the chain correctly. `Salvage::ChecksumMismatch`/`Prefix` `data` is the Flate stage's **output with its predictor undone** (T-06's `decode_chain` already implements predictors), so a reader never interprets PNG row-filter bytes as samples. REPDF has zero predictor or multi-filter streams (eng-r2-fr1: 0 of 3,429 original and 0 of 1,445 damaged Flate streams), so this rule is exercised only by T-03b's synthetic fixtures.
- **Work unit (D-041).** `W` = input bytes consumed by candidate inflates (sum of `in_consumed` returned by each `decompress` call from its checkpoint) + 244 × the number of candidate inflate calls. W is exactly reproducible (0 mismatches over 69 runs, FR-g5) and machine-independent; it replaces every wall-clock figure. Defaults `work = 7e8` (≈2 s on an M-series Mac), `deep_work = 1e10` (≈30 s; covers 100% of first accepts and whole-window certification for 220/221 error, 245/245 ≤4 KiB and 343/343 grammar-flagged streams; for the 4–16 KiB Adler-only class it covers 441/478 first accepts and 280/478 certifications, 100% needs 2.3e10 / 3.3e10, FR-r1-e Part 1). **Deep pool (D-056, replaces revision 3's "≤ 8 damaged streams" switch):** `deep_pool = 8e10` per file; streams whose `work` ran out before any accept draw a **fixed `deep_work`** from the pool (no refunds: a draw is charged in full whether or not the stream uses it, so the allocation never depends on another stream's outcome or on processing order) in a pinned order (smallest raw stream first, then lowest `ObjId`), and a stream that finds the pool empty keeps its `work` result. A deep stream may therefore spend up to `work + deep_work` in total (what eng-r2-fr2 measured). The bound is unchanged (`8 × deep_work + n × work` ≈ 1.01e11 W per file), but a REPDF file with 12–30 damaged streams no longer loses the deep budget entirely, and the order is deterministic. No `Instant`, `Duration` or `SystemTime` appears in this module (clippy `disallowed-types`).
- **Two-phase parallel execution (D-066, eng-r2-q6; measured by eng-r2-fr2).** Phase 1 runs every Flate stream (clean inflate or the search under `work`) as independent tasks over a fixed chunking on `std::thread::scope` with `threads` workers (no rayon). Phase 2 computes the deep allocation **before any deep search runs** (the pinned order above, over the streams that ended phase 1 with no accept and budget or window headroom), then runs the granted streams in parallel, each resuming its saved search state. Results are merged by `ObjId` into the `BTreeMap`. `threads` comes from `std::thread::available_parallelism()` in `jobs.rs` and appears in progress events only, never in any output or report. eng-r2-fr2 on the five worst REPDF C9 files (each saturating the pool): 238–262 s at 1 thread, 70–78 s at 4, 48–52 s at 8 on an M-series Mac, with the per-file digest (grades, W, edits, repaired bytes) **identical at 1, 4 and 8 threads** and every repaired stream equal to the original's decoded bytes; the single-thread worst case (≈5 min per file, most of an hour for ten such files in one drop) is what justifies the scheme, and the thread-independence of the digest is what makes it admissible under DA:423-425.
- Ladder: (1) inflate; `Done` + Adler OK → `Clean`. (2) `Done` + Adler mismatch → keep all output as `ChecksumMismatch` (fallback result). (3) search: checkpoint every 256 input bytes; candidates = all 255 other values at each position; localizer order: inflate-error offset scanning backward from `k` with slack `k+8` over a window of 4,096 bytes (a 16,384-byte window is tried under `deep_work` only: eng-r1-fr1 shows the three misses sit 4.6–6.6 KB before `k`); **Adler-only streams (no error offset) search the full range `[2, len-4)`** for every non-font stream (this is what FR-r1-e and eng-r2-fr2 measured; eng-r2-fr2 notes that 44% of deep W went to runs that found nothing and that non-font Adler-only streams over 16 KiB were repaired in 19 of 89 cases for 17% of deep W: a size cut-off is a tuning question for T-26's numbers, not a correctness one, and is left to D-056's follow-up); accept only on Adler-verified `Done`; continue past the first accept until the window is exhausted or the budget is spent; **survivors are compared by output bytes** (hash each `Done` output; eng-r1-fr1 (c): 6 of 9 second survivors decode to identical output). (4) truncated input → `Prefix`. The TrueType-checksum localizer is T-08b (measured, FR-r1-e); the grammar localizer is T-08c (not-yet, needs T-06's classifier on partial output). The search takes a `Localizer` trait (`fn window(&self, baseline_out: &[u8], trace: &InputTrace) -> Option<Window>`; `fn early_reject(&self, candidate_out_prefix: &[u8]) -> Option<bool>`) so T-08b plugs in without touching the ladder.
- **Grades (D-041).** `Exact`: window exhausted, exactly one distinct output. `Accepted{searched, window}`: at least one accept, budget spent before the window was exhausted, no second distinct output seen. `Ambiguous{outputs: n}`: `n ≥ 2` distinct outputs. `Repaired.data` is always the survivor that is first in the **pinned total order**: body edits before trailer (Adler) edits, then lowest offset, then lowest replacement byte; every distinct survivor's edit list is in `survivors` and goes into the report. Running out of budget after an accept never drops the accept.
- Checkpoint mechanics (FR-08): `DecompressorOxide::clone()` per checkpoint (10,504 B each; the checkpoint count is bounded by `max_search_stream / 256`); `decompress` returns `(status, in_consumed, out_written)`; on `Failed`, `in_consumed` is `k`; on `Done` miniz has compared the Adler-32. `TINFLStatus` is `non_exhaustive`. Raw-deflate streams have no Adler, so their best grade is `Ambiguous{outputs: n}` with `n` counted the same way.
- Tests: each ≤512 B content stream of the C9 golden (seeded) is repaired byte-exact with grade `Exact` (full enumeration of a ≤512 B window costs ≤ 130 K inflates, under `work`); the embedded-font stream (9.6 KB) is `ChecksumMismatch` under `work` with no localizer registered (T-08b turns it into `Exact`; FR-r1-e: a 4–16 KiB stream needs p50 1.9e9 without localization); a synthetic Adler collision (two digit runs permuted, as in eng-r1-fr1) grades `Ambiguous{outputs: 2}` and `data` is the lowest-offset survivor regardless of search order; trailer-byte damage repaired with a `trailer_edit` evidence; budget exhaustion before any accept returns `ChecksumMismatch` (Adler case) or `Prefix` (error case), never `Unrecoverable`; budget exhaustion after an accept returns `Accepted` with the patched bytes; **determinism under budget**: the same stream with `work` set to 1e6, 1e7 and 1e8 gives identical `data` and `edits` whenever the grade is `Exact` or `Accepted`, and `work` reported is identical run to run; a checkpoint-resume equality test (resume from every checkpoint of a clean stream reproduces the output and the Adler); `salvage_all` is cancellable between streams; **deep pool**: a synthetic file with 12 damaged streams and `deep_pool = 3 × deep_work` gives the deep budget to exactly the three smallest streams, in the same order on two runs; **thread independence**: `salvage_all` on the C9 golden and on the 12-stream synthetic with `threads` = 1, 2 and 8 gives byte-identical `SalvageIndex` contents and `work_total` (the eng-r2-fr2 digest test, in miniature); **filter domain**: a C9 hit in (i) T-03b's Flate + PNG-predictor image, (ii) its A85 + Flate content stream, (iii) its Flate + DCT image is repaired with `edits` in the Flate-input domain, and the `FilterStage` records earlier/later filters and parms; **memory (D-072)**: `Clean` entries hold no `Vec` (a size assertion on the enum's largest clean payload) and `decoded()` returns bytes equal to a direct inflate; a synthetic file with one 16 MiB damaged Flate stream at `threads = 8` finishes with the stream `Unsearched` and, with `max_search_stream` raised to 32 MiB for the test, with peak scratch under `scratch_cap` (a counting allocator installed by the test) and the same digest at 1, 2 and 8 threads with admission on; a 5 MiB stream yields `Unsearched` at the default and `Repaired` at 8 MiB. The corpus numbers (FR-14) are re-measured by T-26 on 0.9.1 before anyone quotes them (eng-r1-fr1 already shows 219/221 on the error set).

**T-08b TrueType-checksum localizer for C9 font streams** · defaulted (D-056) · measured (FR-r1-e Part 2: 798 Adler-only REPDF font streams, miniz_oxide 0.9.1)
- Paths: `src/pdf/streams/salvage/ttf.rs` (own sfnt directory parser and checksum, ~80 lines; no skrifa: the directory format is ISO/IEC 14496-22 §4.5 and the checksum is the published 32-bit word sum with `checkSumAdjustment` zeroed for `head`).
- Interface: `TtfLocalizer: Localizer`. Applies only when the stream's baseline decode (the `ChecksumMismatch` output) begins `00 01 00 00`, `true` or `OTTO` and its directory parses (798/798 on the corpus). **Window**: T1 = the failing table with the lowest output offset; the window is the **complete window** = output `[0, end(T1))` minus every table that verified, mapped to input positions through the byte-wise output-after-each-input-byte trace, margin 0 (covered the true byte in 798/798; margin 16 was never binding). When no table fails (29/798: damage in the directory or padding) the window is the gaps only. The tight (T1-only) window is **not** used: it misses 32/798. **Verifier B**: decode a candidate only to `end(T1)`, compare T1's checksum incrementally against the baseline prefix, reject on mismatch, otherwise continue to the stream end for Adler; positions inside the directory fall back to Adler-only (A); a candidate whose checkpoint already lies past `end(T1)` is rejected with no inflate. **Correctness guard**: B assumes the original's T1 checksum was valid (true for 798/798 REPDF originals, not for fonts in general); if B exhausts the window with no accept and budget remains, the window is re-run under A, so a font with a bad original checksum costs more but is never wrongly refused. W counts both decode stages; checksum arithmetic is not counted (estimated ≤15% of decode cost, FR-r1-e method 4).
- Measured effect (the acceptance numbers come from here, not from the TD): fonts > 16 KiB (408) repaired at `work`/`deep_work`: 7.6% / 26.7% without the localizer, **31.1% / 65.0%** with complete window + B; certified 0% / 0% → 0.5% / 32.8%. Fonts 4–16 KiB (370): 98.9% repaired and 85.9% certified at 1e10. Fonts ≤ 4 KiB (20): 100% / 100%. Over all 798: 46.0% repaired at 7e8, 81.6% at 1e10, certified 59.1% at 1e10. A third, font-only budget tier is **not** added in v1 (D-056); T-26 measures the end-to-end effect on the corpus score first.
- Tests: the sfnt parser and checksum on the test font (every table verifies; `head` with adjustment zeroed); a seeded one-byte change inside `glyf` of the test font stream makes exactly `glyf` fail and yields a window inside `glyf`'s input span; a change inside the directory yields the gaps-only window; **the test-font stream (9.6 KB) damaged in `glyf` is repaired byte-exact under `work` with grade `Exact`** (replaces T-08's "ChecksumMismatch until T-08b" expectation; the window is a few hundred positions); the guard: a stream whose *original* `glyf` checksum was deliberately wrong is still repaired (via the A re-run) and the report says so; determinism under budget as in T-08; the B-rejected candidate count equals the A-rejected count plus the no-inflate rejects on two runs.

**T-31 kitty OSC 72 drag tracking** · determined (the protocol as published at https://sw.kovidgoyal.net/kitty/dnd-protocol/, "added in 0.47.0", which FR-r1-b verified states every element below; D-033 amended, D-039, D-057) · one live byte capture outstanding (FR-12)
- Paths: `src/ui/input/osc72.rs`, `src/ui/input/keys.rs`, `src/ui/term.rs` (handshake).
- Clean-room note: kitty is GPL-3. **The published page above is this ticket's single source**; the implementer does not open `kitty/dnd.c`, `docs/dnd-protocol.rst` or any other file from the kitty repository (the `.rst` is the page's source file and lives in the GPL tree; cite the URL). Nothing below needs anything the page does not state (FR-r1-b §A). One correction to the page itself: it prints "OSC is ESC ] (0x1b 0x5b)"; 0x5b is `[`, the OSC introducer is **0x1b 0x5d**; ST is 0x1b 0x5c.
- Handshake at start (Unix only, D-033): write `ESC ] 72 ; t=q ST` then DA1 `ESC [ c`; read stdin raw for at most 300 ms; if a reply whose metadata contains `t=q` arrives before the DA1 reply, opt in with `ESC ] 72 ; t=a ; text/uri-list ST` and the raw splitter owns stdin for the session; otherwise never send `t=a`, hand stdin to crossterm's reader, and **discard and count** any non-handshake bytes read during the window (eng-r3-q3, D-033 amended: never forwarded, on either branch). Match the `t=q` reply on its metadata, not on its payload: the payload is empty today, may or may not be followed by `;`, and may later carry `key=value` support flags, which are ignored. Opt out with `ESC ] 72 ; t=A ST` on every exit path (the page says to send it when done or at exit; what kitty does when a client dies without it is not documented, so the panic hook sends it too).
- Framer: a raw-stdin reader thread splits the byte stream into `ESC ] 72 ; metadata ; payload (ST|BEL)` frames (payload cap 4,096 B per frame, 1 MiB per drop) and everything else, which goes to `keys.rs`: kitty's legacy key encoding, SGR mouse, bracketed paste, resize via SIGWINCH, tested with byte fixtures. Unparsed OSC bytes are never delivered as keys. **Metadata is parsed as order-independent `key=value` pairs; unknown keys and `i=` are tolerated** (the page reserves `i` for multiplexers).
- **Chunking applies to every event, not only `t=r`** (page, top section): a payload over 4,096 encoded bytes arrives as chunks with `m=1` on all but the last; only the first chunk is guaranteed metadata beyond `m`, so continuation chunks may be a bare `m=1;<data>` or `m=0` with no `t` or `x`, and the reassembler attributes them to the open transfer and takes its metadata from the first chunk. A `t=M` (or `t=m`) MIME list can therefore be chunked too. While a chain is open the terminal sends nothing but chunks (or `t=q`).
- Protocol (page sections "Accepting drops", "Drop events", "Requesting data"): `t=m:x=<col>:y=<row>:X=<px>:Y=<px>:o=<1|2|3>;<space-separated MIME list>` with (0,0) top-left and the list sent on the first move and whenever it changes → `CatEvent::DragAt(Some(cell))` and the **required** reply `ESC ] 72 ; t=m:o=1 ; text/uri-list ST` (`o=0` when the pointer is off the cat; until the client replies the terminal tells the OS the drop is not accepted; a reply without a list means "no change"). Leave is the same event with `x=-1:y=-1` and an empty list → `DragAt(None)`; negative cells never mean anything else. `t=M…;<full MIME list>` (the list is mandatory here; no more `t=m` follows) → request the list with `t=r:x=<1-based index of text/uri-list in the t=M list>`; a request before any drop gets `EPERM`, which does **not** terminate anything. Data arrives chunked as above in base64; **concatenate every chunk's payload, then decode once with a padding-indifferent engine** (padding on the last chunk is optional per the page); the chain ends with an empty payload and `m=0`. Decode to an RFC 2483 list (skip blanks and `#`, require `file://`, percent-decode, reject NUL, treat as untrusted; a non-empty host other than `localhost` is rejected: the page says only that `file://` must be supported, so the host rule is ours). On macOS the files may be file promises that exist only while the drop is active (page note; D-039), so every file is read into memory (512 MiB guard) **before** the completion `t=r:o=1` (`o=0` on any failure). `t=R:x=<idx>;<POSIX error name>[:description]` terminates the drop: handle `EPERM`, `ENOENT`, `EIO`, `EINVAL`, `EMFILE`, `ENOMEM`, `EUNKNOWN` and **any other name** as "drop ended" with a hint carrying the description (validated as safe UTF-8, no C0/C1 controls). A drop that originated in the same window is answered `EPERM` by the terminal. After a `t=R` the client still sends `t=r:o=0` (D-057: not stated by the page; harmless under its own rule that a request with no drop in progress is answered `EPERM` and terminates nothing; FR-12 confirms). The files then pass the T-23b drop gate like any paste. Requires kitty ≥ 0.49 (the published changelog's CVE fixes).
- **Observed kitty framing that is tolerance only, never required (FR-r1-b §B):** `:m=0` on every move and drop event, a trailing space after each MIME item, 3,072-byte raw chunks, `x=` repeated on every data chunk and on the terminator, and the exact empty-payload framing of the `t=q` reply. The parser must accept all of these and must not depend on any of them; `m` defaults to 0 when absent, MIME lists are split on whitespace with empties dropped.
- Tests: byte-fixture tests for every frame above, in both the documented-minimal and the observed-kitty framings; chunk reassembly across split reads, including continuation chunks with no metadata and a chunked `t=M` list; unpadded last-chunk base64; cap enforcement; a frame interleaved with key bytes; hostile paths and a `file://host/` URI; every listed error name plus an unknown one; handshake state machine with DA1-first, `t=q`-first (with and without the trailing `;`) and timeout orders, including **leftover bytes discarded and counted, with a bracketed paste inside the window as one of the fixtures** (eng-r3-q3); a mock terminal asserting the `t=m:o=…` reply after the first move and `t=r:o=0|1` on every exit path including after `t=R`. The FR-12 capture becomes one more byte fixture and is the only place the observed-framing items get confirmed without reading source.
- Depends: T-23b, T-19.
