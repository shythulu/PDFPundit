# SRC-0126: repairing corrupted zlib data with the checksum as oracle

**Why it matters:** this is the closest real-world forensic precedent for repairing damaged Flate
streams (GAP-005), not just salvaging them. It is also the only work found that faces ambiguous
repairs head-on, which bears directly on the charter's provenance grade 3.

## Setting (real damage)
- Chip-off dump of a Google Home NAND. The SoC's error-correcting code is undisclosed, so the
  data were read without error correction.
- The bit-flip rate was estimated from the dump itself. Damage is modelled as IID Bernoulli bit
  flips (CLM-0109).
- In the dump, 204 of 920 gzip fragments of the SquashFS image (22%) fail to decompress (CLM-0110).
- **Real-world damage source** for charter §3(a): storage bit rot in dumps taken without ECC
  (DMG-007 realism).

## Method
- **Oracle.** Every single-bit-flip mutation of a corrupted fragment is a candidate. Candidates
  are filtered by three checks: the stream inflates, the Adler-32 matches, and the length is at
  most 128 KiB (CLM-0101).
- **Search pruning.** zlib's read position bounds where the flip can be.
- **Extra oracle.** File lengths from the inode table further filter candidates.
- **Fallback.** Fragments with no single-flip fix go to exhaustive double-flip search.
- **Ambiguity handling.** A few candidates are resolved by manual binary diffing (CLM-0106).
  Many candidates are merged with three-valued logic: bits on which the candidates disagree are
  marked *indeterminate*, and the file is emitted twice (all indeterminate bits set to 1, then
  all set to 0) so a diff shows the unsound regions (CLM-0105).

## Results
- Recovered data rose from 8.32% to 99.68% of bits (CLM-0102).
- Single-flip search: 172 of 204 fragments repaired uniquely; 29 had no candidate; 3 had
  several (CLM-0103).
- Double-flip search: 1 to 40717 candidates per fragment (CLM-0104), at a cost of 22 days to
  more than a year of CPU per fragment (CLM-0107).

## Limitations and future work
- Stream compression (LZMA), where one flip corrupts all later output, is left for future work
  (CLM-0108).
- Resolving candidates manually doesn't scale, and those fragments are excluded from the
  reported ratios.
- There is a single case (one device), and the error model assumes very sparse flips.

## Transfer to PDF (our reading, not the authors')
- Each FlateDecode stream is an independent zlib stream with an Adler-32 trailer, the same unit
  the paper repairs. Its oracle stack maps onto PDF:
  - inflate succeeds;
  - Adler-32 matches;
  - `/Length` agrees;
  - plus a check the paper lacks: the content-stream operator grammar.
- REPDF's C9 files carry 12-30 changed bytes across 11-28 streams (OBS-0002). That is far from
  a 1-2 flip regime, so the brute-force cost and the candidate multiplicity both grow.
- **Charter impact:** "Adler-32 match" alone isn't verification. Grade 3 needs a uniqueness
  test, and grade 2/6 need an explicit *indeterminate* marking (GAP-052). Three-valued output is
  a concrete design for that.
- Code and a reproduction artifact are public: github.com/enssec/squashfs_bitflip_repair (not
  fetched).
