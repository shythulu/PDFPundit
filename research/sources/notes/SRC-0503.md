# SRC-0503 — PDFium recovery behaviour

Permissive licence.

## Recovery techniques (our words)
- **Broken xref (a).** Parsing starts from `startxref`; if the xref chain cannot be loaded, if the root
  cannot be found, or if the root object number is invalid, `RebuildCrossRef` rescans the file word by
  word (strings and hex strings skipped), treating `obj` preceded by two numbers as an object header and
  `trailer` dictionaries as trailers (CLM-0524). The rebuilt table is merged on top of whatever the
  normal parse produced.
- **Object streams (c).** Every object stream parsed during the rebuild contributes compressed entries
  (CLM-0524); `/Type /XRef` streams found are merged as trailers.
- **Which copy wins (i).** Highest generation wins; equal generation → the copy found later (CLM-0525).
  Compressed entries do not override entries with generation > 0 or known object streams, but do
  override a generation-0 uncompressed entry. Later trailers are merged over earlier ones.
- **Stream length (b).** Missing/oversized/unverified `/Length` → distance to the nearer of the next
  `endstream`/`endobj`, minus EOL (CLM-0526, CLM-0527).
- **Truncation (d).** A stream with neither keyword after it is dropped (CLM-0527).
- **Flate (g).** Decoding silently returns the prefix decoded before the first zlib error (CLM-0528);
  output accounting is capped at 1 GiB (CLM-0529).
- **Encryption (h).** No `/ID` → empty file id (CLM-0530).
- **Fonts (f).** Glyphs the font cannot render come from an Arial-based substitute face weighted by
  `/StemV` (CLM-0531); simple fonts without ToUnicode fall back to their encoding (cpdf_simplefont.cpp
  ~L123–133).
- **Page tree (e).** Page count is computed by walking `/Kids` (a `/Pages` without `/Kids` counts as one
  page), with a nesting limit of 1024 levels (cpdf_document.cpp L38, L461–473).
- **Guards.** Parser recursion depth 64 (cpdf_syntax_parser.h L41); maximum object number; 1 GiB Flate
  output cap; linearized/hint-table paths validated separately.

## Test corpus
341 committed PDFs + 562 hand-written `.in` templates expanded by PDFium's own fixup script (OBS-0500).
Many are minimal hand-made reproductions of specific parser bugs (bug_NNNNNN), not natural damage.

## Not checked
XFA; the data-availability (progressive download) validator; image codec error paths; form filling.
