# SRC-0502 — pdf.js recovery behaviour

Permissive licence. Notable for **comments that name the regression PDF behind each workaround**
("fixes issueNNNN.pdf"), which links recovery code to concrete damaged samples in its test corpus
(OBS-0500).

## Recovery techniques (our words)
- **Broken xref (a).** Normal parsing throws an xref-parse exception on trouble; the document is then
  re-parsed in recovery mode, which indexes every object by scanning the file (CLM-0516). The scan
  finds `N G obj`, `xref`…`trailer`, `trailer`…`startxref` (tolerating a missing `startxref`), and
  objects whose body contains `/XRef` (XRef-stream suspects). A missing `endobj` is handled by stopping
  at the next `obj`/`xref`/`trailer`.
- **Which copy wins (i).** Same generation: a later copy replaces the earlier one only if it parses
  (CLM-0517). Different generation: the first one seen stays. Trailer: the **first** valid trailer in
  file order that has `/ID` (and `/Encrypt` if the file is encrypted) wins (CLM-0518) — the opposite
  preference to qpdf/Poppler/MuPDF, which take the last. A "generation fallback" lets a fetch use an
  older generation when validation failed (xref.js ~L906–915).
- **Object streams (c).** Compressed objects are recovered only through XRef streams found by the scan
  (CLM-0519); ObjStm headers are not carved. When fetching from an ObjStm, a wrong index in the xref
  entry is corrected (bug 1978317 comment).
- **Stream length (b).** If `/Length` does not land on `endstream`, a block scan finds `endstream`,
  also accepting the misspelled `endsteam` and cut-short `endstrea` (CLM-0520). Missing length is
  treated as 0 and then searched.
- **Truncation (d).** No endstream-like keyword → the stream is an error (CLM-0521).
- **Flate (g).** The JS inflater ends the stream on a bad block header or read error and keeps the output
  produced (flate_stream.js ~L279–319); the native DecompressionStream path falls back to it on error.
  No Adler-32 verification.
- **Fonts / ToUnicode (f).** Empty font files are treated as absent (CLM-0522) — directly relevant to
  REPDF C7, whose generator blanks font streams with spaces (OBS-0003, main KB). Unparseable font
  programs fall back to standard/system fonts. Without ToUnicode, glyph-name heuristics (Gxx, g00xx,
  Cdd, uniXXXX, some ligatures) produce Unicode (CLM-0523); an incomplete ToUnicode is backed by the
  encoding-derived map (evaluator.js ~L3958–3963).
- **Encryption (h).** Missing `/ID` → empty string (xref.js L142).
- **Page tree (e).** If the last page by `/Count` cannot be loaded, the whole tree is walked and the
  page count is set to the pages actually found (1 if the walk fails) (document.js ~L1750–1830).
- **Guards.** XRef-stream recursion guard via a set of visited offsets; circular `/Pages` detection;
  assorted depth limits (e.g. 40 in catalog.js). No decompression-size cap observed.

## Test corpus
982 committed PDFs + 459 `.link` files (external URLs, many GitHub/Bugzilla attachments from real
users — **may contain personal data**, e.g. invoices; do not download into the repo).

## Not checked
XFA, annotation/forms recovery, image decoders (JBIG2/JPX) error handling, the chunked/range loading
path's interaction with recovery.
