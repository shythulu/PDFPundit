# SRC-0505 — Ghostscript (pdfi) recovery behaviour

**Copyleft (AGPL).** Our own description of behaviour only.

## Recovery techniques (our words)
- **Broken xref (a).** Repair is entered from many places (bad XRef stream, bad xref offsets, failed
  object lookups) but runs at most once per file. It first requires a `%PDF` marker somewhere in the file
  and gives up otherwise (CLM-0540). Pass 1 lexes the file for `x y obj` … `endobj`, skipping stream
  bodies by searching for `endstream`, and records trailers (a later trailer with `/Root` replaces an
  earlier one).
- **Which copy wins (i).** Each object found overwrites earlier entries for that number (last in file
  wins, generation ignored) (CLM-0541); ObjStm members found in pass 2 overwrite uncompressed entries
  (CLM-0542); the highest-numbered `/Type /Catalog` becomes Root (CLM-0543).
- **Object streams (c).** Pass 2 opens every `/Type /ObjStm` and registers its members (CLM-0542).
- **Stream length (b, d).** `/Length` is always verified; a wrong one is replaced by a byte scan for
  `endstream`/`endobj`, justified by AES needing exact lengths; hitting EOF is an I/O error (CLM-0544).
- **Flate (g).** Adler-32 failures are ignored (CLM-0545).
- **Diagnosis taxonomy.** Enumerated tables of 83 named error conditions (pdf_errors.h, CLM-0546) and 96
  warning conditions (pdf_warnings.h) — a model for PDFPundit's `Finding` codes (technical design §19).
- **Encryption (h).** Missing `/ID` → error message, decryption continues without it (CLM-0547).
- **Fonts (f).** Missing/broken fonts are substituted by name mapping or by descriptor flags
  (fixed/serif/italic/bold); CID fonts fall back to a configured CID substitute (DroidSansFallback by
  default) (pdf_font.c ~L237–330, ~L623).
- **Page tree (e).** A `/Count` that disagrees with the pages actually found is corrected in memory
  (pdf_doc.c ~L579–588).
- **Guards.** Object nesting depth 100 (ghostpdf.h L29); loop detection for indirect objects; repair only
  once; object numbers capped for allocation.

## Observation
OBS-0501: header loss alone makes the default `gs` CLI treat REPDF C1 files as PostScript (0/100); with
the PDF interpreter forced it reads all 100; with header + xref loss the forced interpreter fails on
100/100 yet exits 0 — the CLM-0540 rule in action.

## Test corpus
No public regression corpus in the repository (Artifex's test files are not public); 4 PDFs under
`examples/` only (OBS-0500).

## Not checked
The legacy PostScript-based PDF interpreter; pdfwrite output of repaired files; JBIG2/JPX paths.
