# SRC-0206 — SafeDocs CC-MAIN-2021-31-PDF-UNTRUNCATED

**Why it matters:** this is the strongest real-world damage source found in this sweep. It can
also provide the *natural pairs* that charter §3(a) allows.

## What the README establishes (verified quotes)
- Provenance rows: 8,410,704 including the header (CLM-0286). Common Crawl's truncation flag:
  not truncated 6,383,873 (CLM-0285), `length` 2,020,913 (CLM-0280), `disconnect` 5,861 (CLM-0281).
- SafeDocs refetched truncated files from the original URLs (CLM-0284). `REFETCHED_SUCCESS` 1,922,505 (CLM-0282).
- Each row keeps the Common Crawl WARC file and offsets of the original capture (CLM-0283). The
  truncated bytes can therefore be fetched from `data.commoncrawl.org` with a range request, next to the refetched full file.
- Caveats: representativeness cannot be assessed (CLM-0287); some files are not PDFs (CLM-0288).

## Natural-pair protocol (our proposal; not yet run)
1. Sample rows with `cc_truncated in {length, disconnect}` and `fetched_status = REFETCHED_SUCCESS`.
2. Range-fetch the WARC record and extract the HTTP payload, which is the truncated capture.
3. Accept the pair only if the capture is a byte prefix of the refetched file (`fetched_digest` gives
   the refetched file's hash). Otherwise the document changed between crawl (Jul/Aug 2021) and refetch.
4. `length` pairs give a fixed ~1 MB cut on large files. `disconnect` pairs give arbitrary cut points (DMG-100).
5. Licence: Common Crawl terms of use and Digital Corpora terms; the PDFs are third-party documents and
   may contain personal data, so do not commit samples.

About 24% of the corpus's URLs were truncated by Common Crawl: (2,020,913 + 5,861 + 56) / 8,410,703.
This is our arithmetic, not a quote.
