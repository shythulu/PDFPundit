# SRC-0501 — MuPDF recovery behaviour

**Copyleft (AGPL).** Everything below is our own description of behaviour. Coding agents must not be
pointed at this source.

## Recovery techniques (our words)
- **Broken xref (a).** Any non-system failure while loading the xref at open time switches to a
  whole-file repair scan (CLM-0508). Repair is also triggered lazily — once per document — when an object
  fetched through a seemingly valid xref carries a different object number than expected (pdf-xref.c
  ~L2595–2611). The scan looks for a `%PDF-`/`%FDF-` marker in the first KiB, then lexes tokens,
  recognising `int int obj` and top-level dictionaries (treated as trailer candidates that contribute
  `/Encrypt`, `/ID`, `/Root`, `/Info`).
- **Early stop.** If an object cannot be parsed after a root has been seen, the rest of the file is
  ignored (CLM-0511) — a hard omission risk for mid-file damage followed by intact content.
- **Stream length (b).** Declared length first; otherwise byte scan for `endstream` (CLM-0509). For
  unencrypted files the measured length is written back into `/Length` (pdf-repair.c ~L688–703).
- **Object streams (c).** After the scan, every `/Type /ObjStm` found is opened and its header parsed;
  entries are registered as compressed objects (CLM-0510). Broken object streams are skipped with a
  warning; compressed entries whose container is not a live uncompressed object are freed.
- **Which copy wins (i).** Plain objects: the scan list is applied in file order, so later copies
  overwrite earlier ones. ObjStm members do not override an uncompressed copy that lies later in the file
  than the container (CLM-0510, "Bug 708286"). Root: the last indirect root seen; missing `/Root` or
  `/Info` are filled by scanning objects from the highest number down for `/Type /Catalog` and for a
  dictionary with `/Creator` or `/Producer` (an inference). The pre-repair trailer is retained.
- **Truncation (d).** A truncated object at EOF is not allowed to overwrite an earlier good copy
  (pdf-repair.c ~L102–104). A repair-scan search for `endstream` that hits EOF keeps the bytes read
  (less the 9-byte search window).
- **Flate (g).** Premature end, a data error at end of input, and Adler-32 mismatches are warnings; the
  stream ends with the output so far (CLM-0512). Buffered reads can keep a partial buffer ("truncated"
  flag) and abort on a compression-bomb ratio of 200x (min. floor) (CLM-0513).
- **Fonts (f).** A failing embedded font falls back to a built-in (base-14 style) or system font chosen
  by name / CID collection (CLM-0514); substitute fonts are stretched to the PDF's widths
  (pdf-font.c ~L1646). For Identity-encoded fonts with only a substitute font, ToUnicode (or a generic
  TrueType-UCS2 map) is used to reach the substitute's cmap. A failing ToUnicode CMap is ignored with a
  warning.
- **Encryption (h).** Missing `/ID` → warning, derivation without ID bytes (CLM-0515). During repair,
  the `/ID` is taken preferentially from a dictionary that also has `/Encrypt`.
- **Page tree (e).** Cycles and non-page kids are fatal for the fast page map; the loader falls back to a
  slow lookup, and a `/Count` larger than the real number of pages is corrected. No orphan-page scan.
- **Guards.** Object numbers above a fixed maximum are ignored; repair is attempted once; cycle
  detection on parent chains and indirections.
